## 1. 최종 정의
PEGASUS는 예측하고 저장하는 앱이 아니라 다음 순환을 반복하는 학습 시스템이다.

과거 Hist → 현재 경주 사전가공/사전브리핑 → T20/T5 실시간 시장분석 → PEGASUS 최종 1·2·3착/8조합 → 실제결과 → 오차분석/지역특성/Rating/Calibration/Drift 갱신 → 다음 경주 사전가공 → 반복

실제결과는 종료점이 아니라 다음 경주의 입력데이터를 만드는 training event다.

## 2. 최종 목표
- 경주 전 사용자에게 정확한 사전정보 제공
- Hist와 현재 경주조건으로 펀더멘털 확률 생성
- T20/T5 배당으로 시장확률과 자금흐름 반영
- 최종 P1/P2/P3와 순서확률 산출
- 복승2 + 쌍승2 + 삼복2 + 삼쌍2 = 정확히 8조합
- 실제결과와 엔진별 오차 비교
- 실제결과를 지역·거리·등급·두수·주로·배당구조별 데이터로 재가공
- Rating / Track Bias / Calibration / Blend / Regional Prior 갱신
- 개선된 상태를 다음 경주 사전가공에 반영
- Champion/Challenger로 장기 진화

## 3. 절대 금지 규칙
1. 복병=1착, 인기=2착, 실력=3착 같은 강제규칙 금지.
2. 실제착순, 해당 경주 구간기록, FINAL 확정배당 등 미래정보의 예측 feature 사용 금지.
3. 제외/취소/비활성 마번은 출전마, T20/T5, 조합, Hist, Rating, ML, 최종8 어디에도 유입 금지.
4. Prediction Snapshot은 사후 수정 금지.
5. 한 경주 결과로 전체 모델 즉시 교체 금지.

## 8. Post-Race Feature Builder — 필수
실제결과를 단순 outcome으로 저장하지 않는다. 다음 경주용 feature를 생성한다.

### Race Result Features
- 실제 1·2·3착
- 출전두수, 거리, 등급, 주로상태, 함수율
- 게이트 분포, pace profile
- 실제 배당구간
- 인기마 성공/실패
- market surprise level

### Runner Result Features
- finish percentile
- market expected rank vs actual
- model expected rank vs actual
- rating residual
- weight/distance/surface/gate residual
- pace fit

### Jockey/Trainer Features
- expected vs actual
- horse-jockey pair residual
- venue/distance residual

### Betting Structure Features
- F-F, F-M, M-F, M-M, D-F, D-M 등 인기/배당 패턴
- 이 패턴은 prior/설명용이며 착순 강제규칙이 아니다.

## 9. Regional Profile Engine — 새 필수 기능
서울/부경/제주를 단순 region flag로 쓰지 않는다. 각 지역을 독립 데이터제품으로 관리한다.

지역별 저장항목:
- 거리별 인기마 승률
- field-size별 1·2·3착 분포
- 등급별 배당분포
- favorite concentration
- outsider frequency
- 쌍승/삼쌍 배당분포
- gate bias
- pace bias
- track condition bias
- jockey/trainer concentration
- market calibration curve
- blend coefficient history

각 항목은 5년 전체 / 최근1년 / 최근100경주 / 최근20경주를 분리한다.
최근20은 모니터링용이며 단독 판정 기준으로 쓰지 않는다.

표본이 작으면 local estimate를 global estimate로 shrink한다.
regional_estimate = lambda * local + (1-lambda) * global

## 12. Market Baseline

## 19. Two-Stage Blend
1단계: Fundamental + Rating + Track Bias + Hist → p_model
2단계: u_i = a*log(p_model_i) + b*log(p_market_i)
p_blend_i = softmax(u_i)

a/b는 GLOBAL, 서울, 부경, 제주를 분리하고 필요 시 T20/T5 시점별 버전을 둔다.

## 20. Calibration
score를 확률로 직접 표시하지 않는다.

후보:
- isotonic
- sigmoid
- temperature scaling

평가:
- reliability
- Brier
- Log Loss
- ECE

## 21. Ordered Finish
P1(i) = calibrated p_blend(i)
P2(j|i) = position-corrected conditional probability
P3(k|i,j) = position-corrected conditional probability

Plackett-Luce 기본 + Harville bias 보정 후보(Henery/Stern 또는 empirical correction).

## 22. PEGASUS Final 1·2·3착
최종은 joint probability 순열로 결정.

예:
1위 4→10→9 3.82%
2위 4→9→10 3.11%
3위 10→4→9 2.74%

메인 출력은 1위 시나리오.

## 23. 최종 8조합
- 복승 2
- 쌍승 2
- 삼복 2
- 삼쌍 2

선정기준:
1. ordered probability
2. market odds
3. expected value
4. uncertainty

고배당 자체를 우선하지 않는다.

## 66. 설계 검증 결론
기존 히스트.md와 배당디자인.md에는 예측·결과비교·온라인업데이트의 골격은 있었지만 다음 네 항목이 최종 폐쇄루프 관점에서 부족했다.
1. 지역별 경주특성을 독립 데이터제품으로 만드는 Regional Profile
2. 학습결과를 경주 전에 사용자에게 보여주는 Pre-Race Briefing
3. 실제결과 후 다음 경주 feature를 미리 만드는 Materialization
4. Offline Hist와 Android 실전 feature 계산의 Training-Serving Parity

본 문서에서 네 항목을 필수기능으로 승격했다.

최종 구조는 예측 → 결과 → 저장이 아니다.
예측 → 실제결과 → 오차분석 → 지역특성 재가공 → Rating/Track/Calibration 갱신 → Feature Materialization → 다음 경주 사전브리핑 → 다음 PEGASUS 1·2·3착 이다.

## 67. 최종 한 문장
PEGASUS는 실제 경주결과를 단순 저장하지 않고, 결과를 지역·조건·말·기수·조교사·시장 특성으로 재가공해 최신 Feature State를 만들고, 그 상태를 다음 경주의 사전브리핑과 Fundamental/Market/Blend/Ordered-Finish 확률에 다시 투입함으로써 경주가 반복될수록 검증 가능한 방식으로 진화하는 폐쇄루프 예상착순 시스템으로 구현한다.
