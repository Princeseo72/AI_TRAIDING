# 히스트.md — PEGASUS Historical + Online Learning Engine Contract

> 상태: 임시 설계 기준문서
> 목적: 5년 과거 경주 데이터(Hist)와 실전 T20/T5 데이터를 결합하여 예측엔진이 지속 학습하도록 하는 구조를 고정한다.
> 원칙: 이 문서는 런타임 데이터 파일이 아니다. 실제 Hist JSON/SQLite/모델은 반드시 이 문서의 스키마·버전·학습·검증 규칙을 따른다.

---

## 1. 핵심 결론

현재의 역할형/배당형 엔진은 단순 규칙 기반으로 끝내지 않는다.

최종 구조는 다음 4층으로 고정한다.

1. **Historical Batch Layer**
   - 서울/부경/제주 최근 5년 경주결과
   - 실제 1·2·3착
   - 단승/복승/쌍승/삼복승/삼쌍승 확정배당
   - 출전두수, 거리, 등급, 주로, 인기, 전적, 기수, 조교사 등
   - 장기간 반복 패턴과 기본확률(prior) 학습

2. **Live Race Layer**
   - 당일 출전마 검증
   - T20 / T5 배당
   - Q20 / Q5
   - LMI
   - Cross-Pool Divergence
   - 실시간 시장 변화 특징
   - Hist에서 생성된 사전확률과 결합

3. **Post-Race Online Learning Layer**
   - 예측 당시 스냅샷을 변경하지 않고 보존
   - 실제 1·2·3착 및 확정 승식과 비교
   - 온라인 모델/앙상블 가중치/확률보정만 작은 폭으로 업데이트
   - 1경기 결과가 전체 모델을 뒤집지 못하도록 제한

4. **Periodic Retraining Layer**
   - 일정 경주 수 또는 일정 기간마다 Hist + 신규 실전 데이터를 합쳐 전체 재학습
   - 새 모델은 Challenger로 생성
   - Walk-forward 검증 통과 시에만 Champion 승격

## 2. 복병 1착 고정 규칙 폐기

다음 규칙은 금지한다.

- 복병마이므로 1착
- 인기마이므로 2착
- 실력마이므로 3착

복병/인기/실력은 **역할 특징(feature)** 이며 착순 라벨이 아니다.

역할형은 다음 질문을 풀어야 한다.

- 이 말이 1착할 확률은?
- 이 말이 2착할 확률은?
- 이 말이 3착할 확률은?
- 현재 조건에서 복병성이 실제 적중에 도움이 되는가?

고배당 시나리오는 수익기회일 뿐 기본확률을 대체하지 않는다.

## 4. 학습 데이터의 시간 경계

예측 시점 t에서 사용할 수 있는 정보는 t 이전 정보와 그 시점까지 공개된 실시간 정보뿐이다.

금지:
- 실제 착순
- 확정 승식배당
- 경주 종료 후 수정된 데이터
- 미래 경주의 통계
- 전체 기간을 이용한 normalization/target encoding

모든 과거 학습/검증은 시간순으로 진행한다.

### 4.1 검증 방식

Random K-Fold 금지.

사용:
- Expanding Walk-Forward
- Sliding Walk-Forward
- Progressive Validation

예:
Train 2022 -> Test 2023Q1
Train 2022~2023Q1 -> Test 2023Q2
...
Train 과거 전체 -> Test 가장 최근 구간

## 5. Historical Batch Model

### 5.1 주력 모델

경마는 다중 말의 상대순위 문제이므로 일반 단일 분류기보다 Learning-to-Rank 계열을 우선 검토한다.

주력 후보:
- LightGBM LambdaRank
- XGBoost ranking
- CatBoost ranking

별도 확률모델:
- 1착 확률
- 2착 조건부 확률
- 3착 조건부 확률
- Exacta / Trifecta 순서확률

### 5.2 Ranking 목표

순위품질:
- NDCG
- MAP
- MRR

실전 성능:
- 1착 적중률
- TOP3 포함률
- Exacta 적중률
- Trifecta 적중률
- Log Loss
- Brier Score
- Calibration Error

랭킹 점수가 좋더라도 실제 승식 적중이 떨어지면 Champion으로 승격하지 않는다.

---

## 6. 확률 순위 모델

단순 점수 정렬만 하지 않는다.

권장:
- Plackett-Luce 계열 순위확률
- pairwise win probability
- position-specific probability

목표:
P(horse=i is 1st)
P(horse=j is 2nd | first=i)
P(horse=k is 3rd | first=i, second=j)

이를 통해 쌍승/삼쌍 조합은 순서확률로 계산한다.

## 7. 실시간 Live Engine

실전 경주에서 다음 순서로 동작한다.

### Phase A — Historical Retrieval

현재 경주와 유사한 Hist 조건 검색:
- venue
- distance
- grade
- field_size
- popularity structure
- final/available odds regime
- horse form profile
- jockey/trainer profile

출력:
- historical_prior_1st
- historical_prior_2nd
- historical_prior_3rd
- scenario_frequency
- similar_race_count

### Phase B — T20 Update

T20 시점:
- Q20
- popularity shift
- Hist prior와 현재 시장의 차이
- 초기 실시간 posterior 계산

### Phase C — T5 Update

T5 시점:
- Q5
- LMI
- odds compression
- Cross-Pool Divergence
- T20 -> T5 변화량

Hist prior에 실시간 신호를 반영하여 posterior 재계산.

### Phase D — Final Prediction

출력:
- Role Engine
- Odds Engine
- Historical Engine
- Online ML Engine
- Consensus Engine

서로 같은 결과가 나왔을 때는 **독립성 검증 후에만** 합의도 상승.

## 10. Historical Engine

Hist에서 현재 경주와 유사한 과거 경주를 검색한다.

두 방식 병행:

### A. Group Prior
예:
서울 / 1200m / 10두 / 국5 / 인기구조 1-2-중위

과거 동일 bucket의:
- 1착 인기구간 빈도
- 2착 인기구간 빈도
- 3착 인기구간 빈도
- Exacta payout distribution
- Trifecta payout distribution

### B. Similarity Retrieval
현재 feature vector와 과거 경주 feature vector의 거리 계산.

유사경주 TOP-K에서:
- 실제 1·2·3착 패턴
- 인기/배당 시나리오
- Exacta/Trifecta 패턴

을 가져온다.

Hist 전체를 매번 원격조회하지 않고 로컬 인덱스에서 검색한다.

## 11. Online Learning

경주 종료 후 다음 순서만 허용한다.

1. prediction snapshot 저장
2. 실제 결과 확인
3. progressive evaluation
4. calibration update
5. ensemble weight update
6. lightweight online learner update
7. drift detector update
8. Challenger 상태 갱신

### 11.1 한 경주로 전체 모델 재학습 금지

매 경주 후 가능한 업데이트:
- 확률 calibration
- 앙상블 가중치
- 지역별 prior
- online linear/logistic weights
- Bayesian posterior

전체 LambdaRank/GBDT 재학습은 배치로 분리한다.

## 12. Concept Drift

경마 시장/기수/말집단/배당행동은 시간에 따라 변한다.

감시 대상:
- Log Loss
- Brier Score
- 1착 적중률
- TOP3
- Exacta
- Trifecta
- odds calibration
- feature distribution

드리프트 감지 후보:
- ADWIN
- Page-Hinkley
- rolling-window degradation

드리프트 발생 시:
- 즉시 Champion 덮어쓰기 금지
- 최근 데이터 가중치 증가
- Challenger 재학습
- 과거 window 축소 검토

## 13. Champion / Challenger

Champion:
현재 실전 사용 모델.

Challenger:
새 데이터로 학습된 후보 모델.

승격 조건:
- 시간순 holdout에서 Champion 이상
- 최근구간에서도 성능 저하 없음
- calibration 악화 없음
- Exacta/Trifecta 주요지표 악화 없음
- 최소 표본 충족

한 경기 승패로 승격/강등 금지.

모든 모델 버전은 롤백 가능해야 한다.

## 15. Contextual Bandit 사용 범위

Contextual Bandit을 **착순 예측 주력모델로 사용하지 않는다.**

이유:
경주 종료 후 모든 출전마의 실제 순위가 관측되므로 일반적인 bandit의 partial feedback 문제가 아니다.

대신 다음 용도로만 후보:
- 여러 예측엔진 중 어떤 정책을 선택할지
- 8개 조합 중 어떤 위험/수익 프로파일을 우선할지
- 자금배분 정책 비교

사용할 경우 반드시 offline policy evaluation 후 적용한다.

## 16. 확률 Calibration

score를 confidence로 표시하지 않는다.

예:
모델이 1착확률 0.40이라고 출력했으면,
장기간 유사한 예측의 실제 1착 비율이 약 40%에 가까워야 한다.

검증:
- Reliability Diagram
- Brier Score
- Log Loss
- venue별 calibration
- odds band별 calibration

## 22. 성능 기준

실전 앱은 Hist 원본 5년치를 매 경주마다 전체 scan하지 않는다.

권장:
- JSONL = 원본 보관
- SQLite/Parquet = 학습/조회
- precomputed aggregate index
- similarity vector index
- 최근 모델/통계 메모리 cache

목표:
- historical retrieval < 100ms
- local model inference < 100ms
- online update < 250ms
- 원격 네트워크 실패가 로컬 Hist 예측을 막지 않음

## 25. 연구 근거 메모

- 2025년 국내 연구에서 KRA 9,140개 경주 데이터를 이용한 Learning-to-Rank/LambdaRank 비교가 보고되었고 CatBoost가 NDCG/MAP에서 강했으며, 실제 베팅 적중에서는 LightGBM/XGBoost가 더 나은 결과를 보였다.
- Vowpal Wabbit은 contextual bandit, offline policy evaluation 및 online learning 구조를 제공한다.
- River는 progressive validation과 drift detector(ADWIN 등), incremental learning을 제공한다.
- Feast의 핵심 원칙은 historical point-in-time correct retrieval과 online latest feature serving의 일관성이다.
- MLflow Model Registry의 champion/challenger alias 및 version lineage 개념은 안전한 모델 승격/롤백에 적합하다.
- 확률모델은 Brier/Log Loss와 reliability curve로 calibration을 검증해야 한다.
