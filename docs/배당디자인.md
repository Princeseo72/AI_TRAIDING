# 1. 최종 제품 목적

PEGASUS 앱의 목적은 고배당 조합을 억지로 만드는 것이 아니다.

목표는 다음이다.

1. **시장배당이 제시하는 확률을 기준선으로 삼는다.**
2. **5년 Hist와 말·기수·조교사 상태를 이용해 시장보다 나은 정보가 있는지 찾는다.**
3. **T20 → T5 실시간 배당 변화로 마지막 시장정보를 반영한다.**
4. **최종 1·2·3착을 확률로 산출한다.**
5. **쌍승·삼쌍승은 순서확률에서 파생한다.**
6. **실제 결과와 비교해 다음 경주에서 조금씩 개선한다.**
7. **개선되지 않는 학습요소는 자동으로 비중을 낮추거나 Challenger로 격리한다.**

# 4. 가장 중요한 금지 규칙

아래는 코딩 시 절대 위반하지 않는다.

## 4.1 착순 강제 규칙 금지

금지:
- 복병마 = 1착
- 인기마 = 2착
- 실력마 = 3착

복병/인기/실력은 **설명용 feature**일 뿐 착순 label이 아니다.

## 4.2 미래정보 누수 금지

예측 시점 이전에 알 수 없던 정보는 feature 금지.

금지:
- 실제 착순
- 해당 경주의 최종 구간기록
- FINAL 확정배당을 T5로 사용
- 경주 종료 후 갱신된 정보
- 미래 구간을 포함한 normalization

## 4.3 제외마 누수 금지

제외/취소/비활성 마번은:
- T20 입력행 생성 금지
- T5 입력행 생성 금지
- 조합입력 금지
- 분석 입력 금지
- Hist similarity 후보 금지
- ML feature 금지
- 승식 조합 금지

UI에는 제외마 목록을 별도로 표시하지 않는다.

## 4.4 하나의 경기로 모델 전체 교체 금지

매 경주 후 가능한 것은:
- calibration 소폭 업데이트
- ensemble/blend 계수 소폭 업데이트
- rating 증분 업데이트
- regional prior 업데이트

전체 Ranking 모델 재학습은 배치에서만 수행.

## 8.1 사용자 입력

- 날짜
- 지역
- 경주번호
- 검빛/KRA 불러오기 버튼

## 8.2 내부 처리

순서 고정:

1. 검빛/KRA 경주 identity 확인
2. 출전마 검증
3. 제외마 내부 제거
4. Hist manifest 버전 확인
5. 해당 경주 Hist context prefetch
6. Rating state prefetch
7. 당일 앞선 경주 Track Bias 조회
8. ML/Champion 상태 조회

## 8.3 화면 표시

기본:

```text

유효 출전 9두

Model: CHAMPION v14
지역모델: JEJU v7
Track Bias: 초기 / 표본 1경주
```

### 상태색

- 초록: 사용 가능/검증 완료
- 노랑: fallback/표본 부족
- 빨강: 분석 차단이 필요한 오류
- 회색: 선택정보/참고정보

# 12. Market Baseline Engine

## 12.1 계산

```text
p_raw(i) = 1 / odds(i)
p_market(i) = p_raw(i) / sum(p_raw)
```

## 12.2 반드시 저장

- T20 market probability
- T5 market probability
- CLOSE market probability(optional)
- market rank
- market entropy

## 12.3 역할

시장 모델은 경쟁 대상이자 fallback이다.

모델 장애 시:

```text
Final fallback = calibrated market probability
```

분석 전체를 무조건 실패시키지 않는다.

# 17. Two-Stage Blend

핵심 공식:

```text
u_i = a * log(p_model_i) + b * log(p_market_i)
p_final_i = softmax(u_i)
```

## 17.1 계수 범위

초기 hard-coded 고정값으로 장기 운영하지 않는다.

계수는:
- GLOBAL
- 서울
- 부경
- 제주

별도 버전.

## 17.2 화면 표시

```text
시장비중 b: 0.71
모델비중 a: 0.29
지역계수: JEJU-v7
```

사용자에게 복잡한 수학은 숨기고 세부보기에서 표시.

```text
3착확률 15.1%
```

로 표시.

Calibration 상태:

- CALIBRATED
- LOW SAMPLE

# 19. Ordered Finish Engine

최종 예상착순 핵심.

## 19.1 1착

```text
P1(i) = calibrated p_final(i)
```

## 19.2 2착

```text
P2(j | i)
```

Plackett-Luce 기본값에 position correction 적용.

## 19.3 3착

```text
P3(k | i,j)
```

Harville 편향 보정/empirical calibration 사용.

## 19.4 최종 예상착순

가장 높은 joint probability 순열을 선택.

예:

```text
1위 시나리오 4→10→9 : 3.82%
2위 시나리오 4→9→10 : 3.11%
3위 시나리오 10→4→9 : 2.74%
```

메인 예상착순은 1위 시나리오.

# 23. 최종출력 세 번째 영역 — 확률표

TOP 5만 기본 표시.

| 마번 | P1 | P2 | P3 | 시장P | 모델-시장 차이 |
|---|---:|---:|---:|---:|---:|
| 4 | 28.4 | 21.0 | 14.7 | 22.1 | +6.3 |
| 10 | 19.3 | 24.2 | 18.1 | 18.7 | +0.6 |
| 9 | 14.1 | 17.5 | 22.6 | 12.0 | +2.1 |

### 색상

- +유의미 차이: 초록
- 시장과 유사: 회색
- 시장보다 낮음: 주황
- 과신 위험/표본부족: 노랑

전체마 보기 버튼 제공.

# 24. 최종출력 네 번째 영역 — 최종 승식 8조합

기존 8개 제한 유지.

## 복승 2
## 쌍승 2
## 삼복승 2
## 삼쌍승 2

각 조합 표시:

```text
쌍승 1
4 → 10
조합확률 8.2%
현재배당 7.4
EV 0.61
근거: Final Blend
```

### 중요

EV < 1이어도 조합 후보로 보여줄 수 있으나:
- `가치 부족` badge 표시

EV 기준은 추천/배팅 판단용이지 예상착순 자체를 바꾸지 않는다.

# 50. 최종 설계 문장

PEGASUS의 최종 판단 구조는 아래 한 줄로 정의한다.

**과거 Hist가 기본 기억을 만들고, Rating이 현재 능력을 갱신하며, 당일 Track Bias가 환경을 보정하고, T20/T5 배당이 시장 현재정보를 제공하며, Two-Stage Blend와 Calibration이 이를 통합하고, Ordered Finish Engine이 최종 1·2·3착과 승식확률을 결정한다.**

이 문서를 코딩 구현의 기준으로 사용한다.
